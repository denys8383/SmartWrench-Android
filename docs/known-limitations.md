# Обмеження та ризики
- **Технічний борг:** IP адреса сервера захардкоджена в `NetworkClient` на мобільному клієнті.
- **Ризики:** Відсутність повноцінної бази даних, логіка AI з часом стане занадто великою для одного файлу.

# Відомі обмеження (Known Limitations — ЛР №4)

1. **Відсутність черги офлайн-запитів:** Застосунок реалізує базовий рівень складності. Запити, зроблені без активного з'єднання з сервером, не зберігаються у статусі «очікує» для подальшої відправки.
2. **Масштабованість сховища:** Зберігання списку об'єктів у вигляді JSON-рядка в `Preferences DataStore` є оптимальним для локальної історії з десятками чи сотнями записів. При збільшенні обсягу даних до десятків тисяч записів рекомендовано мігрувати на реляційну базу даних `Room`.
3. **Локальність:** Дані прив'язані до конкретного пристрою і видаляються разом із деінсталяцією мобільного застосунку.

# Відомі обмеження та компроміси (Оновлення ЛР №5)

1. **Ручне впровадження залежностей (Manual DI):** Створення графа об'єктів виконується через `DiagnosticViewModelFactory` у `MainActivity` без використання DI-фреймворків (Hilt/Koin), щоб не ускладнювати конфігурацію збірки односторінкового застосунку.
2. **Зв'язування збереження історії через лямбду:** Колбек `onSuccessSaveHistory` передається у `DiagnosticViewModel` для збереження сумісності з `HistoryManager` із ЛР №4.
